SOUNDTRACK PLAYER — GITHUB PAGES

1. Keep index.html in the repository root; put active audio in used-songs/.
   If your existing website already has an index.html, use a separate soundtrack
   repository rather than overwriting your existing home page.
   Enable GitHub Pages for that root. Open the published page, not the GitHub file.

2. On the usual username.github.io/repository/ address the player automatically
   lists audio files in used-songs/ using GitHub's public API. Audio streams from Pages.
   The playlist starts in a random order each time the page loads.\n   Add a cover next to a song in used-songs/, using the same filename stem,\n   e.g. Song.mp3 plus Song.jpg. Supported images: JPG, JPEG, PNG, and WebP.\n   The cover appears in the player while that song is selected; missing covers\n   use the built-in artwork. Images are read from the same public Pages folder. MP3 is a good starting format.
   Format support depends on the listener's browser.

3. Optional: edit CONFIG near the beginning of the script in index.html.
   Fill tracks for custom titles, artist names, notes, and order. Example:
   tracks: [
     {file:'01-first-song.mp3',title:'First Song',artist:'Your name',info:'Opening theme'},
     {file:'02-second-song.mp3',title:'Second Song',artist:'Your name'}
   ]
   Manual tracks bypass GitHub API availability/rate limits. Filenames must
   match exactly, including capitals and extensions. Use filenames relative to
   used-songs/, without the folder prefix.
   For a custom domain, set owner and repo. Set branch when the audio lives on
   a publishing branch other than your repository default. Root publishing is
   assumed; a /docs publishing source requires manual track configuration.

MOVING NEW MP3 UPLOADS

Upload active songs directly into used-songs/. Alternatively, upload MP3s to the
root and run Actions > Move songs > Run workflow. This manually triggered workflow
moves only root MP3 files (including .MP3) into used-songs/ on main. It leaves all
other files and subfolders alone. A duplicate destination filename stops the
whole move before it starts; existing files are never overwritten.
GitHub requires permission for the workflow to write to main. A commit made by
the workflow's built-in token may not trigger a Pages rebuild; if necessary, rerun
the Pages deployment after moving files. Uploading directly into used-songs/ is
simpler for routine additions.

BEHAVIOR AND LIMITS

Play/pause, next, previous, seek, volume, shuffle, repeat-all, and repeat-one.
Tap Repeat to cycle off → playlist → one track → off.
Shuffle goes through every track once before a repeat-all cycle starts again.
Browsers require the visitor to press Play; there is no autoplay on arrival.
iPhone volume may need the device's physical volume controls.
No download links or save controls are provided. Public audio remains accessible.
